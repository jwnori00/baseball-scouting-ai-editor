# 자동 플레이 탐색 검증판 — 투수·타자 사용법

이 버전은 **구도·국소 움직임·OCR 규칙으로 실제 후보를 생성**합니다.
기존 수동 편집 개발판과 달리 탐색 버튼이 새 `rules.analyze_plays` 엔진을 실행합니다.
일반 동작 모델이 야구라고 하지 않았다는 이유로 후보를 버리지 않습니다.
CPU로 실행하며 Python·pip·FFmpeg·모델 다운로드를 사용자에게 요구하지 않습니다.

## 사용할 수 있는 범위

기본 프로필은 제공된 LMB 샘플과 같은 검은 여백/투구 카메라/우측 자막 배치를 대상으로 합니다.
1280×720 이외 해상도에서도 같은 정규화된 배치이면 분석할 수 있지만 별도 검증은 필요합니다.
다른 방송 배치, 다른 팀·이닝·교체·견제·리플레이의 일반 성능은 아직 보증하지 않습니다.
필수 설정은 ZIP 안 `profiles/lmb-telemetry-v1.json`, OCR 영어 자료와 도구도 ZIP에 포함됩니다.

## 공통 순서

1. **영상 선택**에서 1개 또는 한 경기의 여러 파일을 선택하고 위/아래로 경기 순서를 맞춥니다.
2. **투수/타자**, 이름을 입력합니다. 팀은 TIJ/JAL 같은 표기 또는 지원된 팀 별칭을 입력하면
   이름 외 확인 근거로 사용합니다. 등번호는 프로필에 OCR 영역이 있을 때만 자동 근거로 사용합니다.
   현재 기본 프로필의 영상 등번호 판독은 검증되지 않았습니다.
3. **자동 플레이 탐색 시작** → 프로젝트 저장 위치를 정합니다.
   큰 원본의 해시 확인 후 순차 분석하며 영상 전체를 메모리에 올리지 않습니다.
4. 기본 목록에서 대상·신원미확정 후보를 확인합니다. 첫 후보처럼 팀 정보가 안 나온 장면은
   후보를 버리지 않고 신원 미확정으로 표시합니다. 필요하면 **판단 근거**를 봅니다.
5. **후보 재생**, 시작·종료 수정, **대상 선수 확인**, **수정·검수 승인** 또는 **제외**를 사용합니다.
   **누락 후보 보조 추가**는 실제로 빠진 장면을 확인했을 때만 사용합니다.
6. 전체/투구별/확정 타석별 형식을 고르고 **MP4 저장**합니다. 승인한 구간만 출력합니다.
   기존 출력 폴더를 덮어쓰지 않습니다.

## 투수 모드

모든 결과의 투구를 같은 규칙으로 수집합니다. 볼/스트라이크/파울/안타를 선별하지 않습니다.
준비·투구·반환/안정화 동작을 하나의 움직임 에피소드로 합치고 정지 준비가 다시 있는 경우
다음 투구 후보로 나눕니다. 투수 교체로 읽힌 이름이 바뀌면 이전 확인 근거를 초기화합니다.
견제 근거가 모자라면 투구/견제 불확실 경고를 남깁니다. **프로젝트 메뉴**에서 원본 확인 후
투구/견제/리플레이로 분류합니다. 견제는 기본 출력에서 제외되며 **승인한 견제도 출력**으로 선택할 수 있습니다.
이 동작 분류의 실제 견제 영상 성능은 아직 미검증입니다.

## 타자 모드

한 투구는 하나의 `PitchEvent`, 여러 투구가 속한 타석은 `PlateAppearance`로 저장됩니다.
파울처럼 카운트가 그대로여도 움직임 후보를 유지합니다. 타자명/이닝 변경, 카운트 초기화를
타석 경계 근거로 사용하며 정보가 없으면 타석 연결 미확정으로 표시합니다.
타석별 출력 전에는 **선택 타석 그룹 확정**을 사용합니다.
잘못 묶였으면 프로젝트 메뉴 **선택 후보부터 새 타석 / 이전 타석과 합치기**로 보완합니다.

## 신원·경계·리플레이 검수

- 이름+팀/등번호 근거가 모자라면 자동 확정하지 않습니다. 다른 선수 가능성/OCR 오류도 별도 목록에 보존합니다.
- 카메라 컷만으로 투구를 만들지 않습니다. 중계 구도와 투수 영역 움직임 근거가 함께 필요합니다.
- 일반 동작 모델은 필수 조건이 아닙니다. 현재 기본 경로는 해당 모델이나 그 가중치를 쓰지 않습니다.
- 반환 송구까지 보이는지 직접 확인합니다. 방송에서 사라진 장면은 생성하지 않습니다.
- 필드 장면이 이어지면 수비·주루가 끝나기 전에 자르지 않도록 보수적으로 확장합니다.
  의미적으로 아웃/세이프·홈런 주루 종료를 이해하는 모델은 없으므로 종료 여유와 절단 여부를 검수해야 합니다.
- 명시적 리플레이 OCR 또는 같은 움직임 프레임 시퀀스의 완전 일치는 제외 근거로 씁니다.
  다른 앵글·재압축 리플레이는 놓칠 수 있습니다. 제외된 리플레이를 투구로 재분류하기 전에는 출력하지 않습니다.
- **누락 의심 구간**은 투구 구도 공백 또는 OCR 투구 수 증가의 불일치입니다. 실제 투구를 발견했다는 뜻이 아닙니다.

## 중단·재개 및 1.2GB 이상 원본 진단

중단 버튼은 현재 프레임/OCR 처리 후 멈추고 프로젝트와 `.sqlite` 체크포인트를 보존합니다.
같은 프로젝트·같은 캐시로 다시 시작하면 저장된 관측을 재사용합니다.
다른 선수 분석도 같은 원본·설정의 캐시를 재사용할 수 있습니다.
검수 승인 기록이 있는 프로젝트는 보호되므로 새 프로젝트를 만들어 같은 캐시를 사용합니다.

오류가 나면 저장된 프로젝트를 열고 **프로젝트 → 탐색 결과 CSV·JSON 저장**을 실행합니다.
원본 ID·실패 시각·오류·캐시 사용·후보·누락 의심 구간을 로컬에 기록합니다.
원본을 GitHub에 올리지 않습니다. 이 환경에서 사용자의 1.2GB 원본을 읽은 것은 아닙니다.

## 실제 성능 검증용 독립 정답

한 번의 성능 검증 작업으로 별도 검수자가 **프로젝트 → 검증용 독립 정답 작업 시작**에서
원본 전체 샘플을 보고 투구를 표시·승인하고 타석 그룹을 지정한 JSON을 저장합니다.
이는 검증용 라벨링이며 평소 자동 탐색 작업에서 투구 시각을 입력하라는 뜻이 아닙니다.
자동 후보를 복사만 한 것을 누락 검증용 독립 정답으로 간주하지 마세요.

포터블 EXE에는 개발 도구 없이 비교할 수 있는 선택적 진단 명령도 있습니다:

```powershell
.\BaseballScoutingAIEditor.exe --compare-reviewed "D:\local\auto.json" "D:\local\independent-reference.json" "D:\local\validation" --complete-reference
```

`--complete-reference`는 검수자가 해당 원본 전체를 독립적으로 확인했을 때만 지정합니다.
생략하면 정밀도·재현율·신원 정확도는 `NOT_EVALUATED`이며 구간 매칭/오차만 참고합니다.
결과는 JSON/CSV이며 원본을 전송하지 않습니다. 편집 시간 감소는 실제 측정값이 없으면 미평가입니다.
