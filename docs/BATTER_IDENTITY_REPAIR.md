# 타자 식별 오류 경로 수정 · preview6

이 버전은 오류 표시·타석 생성·자막 근거 수집을 고친 시험판입니다.
**유니폼 등번호 자동 인식·선수 추적·KBO 전체 경기 타자 식별 완성판이 아닙니다.**

## 실제 재사용한 자료

로컬 영상 47개 파일(내용 해시 기준 45개)에 실제 접근했습니다. 사용자 출력 영상 등도 포함하므로 45개의 독립 경기라는 뜻은 아닙니다.
기존 scene-labels-v2.json의 156개 프레임은 모두 원본 경로가 존재합니다.
학습 25개 파일/124프레임과 기존 검증 8개 파일/32프레임입니다.
해당 모델의 라벨은 other/pitch_camera이며 타자 신원·유니폼 번호 라벨이 아닙니다.
구도 가중치는 재사용했고 새 선수·동작·등번호 모델을 학습하지 않았습니다.
기존 일반 R3D-18 동작 모델의 실패 기록도 확인했으며 신원 식별기로 배포하지 않았습니다.

신규 OCR 확인은 기존 학습용 KBO 영상 12개에서 뽑은 프레임을 개발 자료로 사용했습니다.
기존 구도 검증 집합의 다른 경기 그룹 프레임 4개는 자막 읽기 확인에 사용했습니다.
이는 독립 전체 경기의 투구·타석·선수 정답을 갖춘 최종 시험이 아닙니다.
독립적인 타자 신원/유니폼 번호 학습·시험 자료는 현재 확보된 manifest에 없습니다.

## 재현한 실패

- 박정권 JSON: 763개 후보, 대상 확인 0, 타자 OCR 근거 0, 단일 후보 그룹 763개.
- 정수빈 JSON/SQLite: 117개 후보, 대상 확인 0, 10,904개 캐시 행에 OCR 입력 0.
- 박정권 SQLite, 두 대용량 경기 원본, 추가 프로그램 녹화는 32MiB 전송 제한으로 열지 못했습니다.
- 해당 대용량 영상을 디코딩하거나 박정권·정수빈의 실제 모든 타석을 확인했다고 주장하지 않습니다.

## 실제 수정

1. 문자 영역이 없는 방송형 타자 모드에서 전체 프레임 문자 탐색을 실제 분석에 연결했습니다.
   KBO 또는 한글 이름은 kor+eng, NPB는 jpn+eng을 선택합니다.
   명시적으로 지정한 타자명 영역과 투수 분석 프로필은 보존합니다.
2. 이름만 읽힌 경우는 name_hint로 남기며 선수 확정과 구분합니다.
   근처의 명시적 타자/타격 통계 문맥과 관측된 팀 또는 표기 번호를 추가 근거로 사용합니다.
   자막에 읽힌 번호는 caption_label로 기록하며 실제 유니폼 번호라고 표현하지 않습니다.
   역할 근거가 없으면 전체 화면에서 이름을 읽었더라도 현재 타자로 확정하지 않습니다.
3. OCR TSV의 따옴표 때문에 여러 줄이 하나의 문자로 합쳐지는 파서 문제를 고쳤습니다.
   기존 OCR 캐시는 다른 키로 보존하고 수정된 파서 결과를 새 키에 저장합니다. 따라서 OCR 재분석은 필요할 수 있습니다.
4. 투구 뒤에 등장한 타자 자막으로 앞선 투구의 타자 ID를 바꾸지 않도록 제한했습니다.
5. 타자 근거가 없는 투구를 후보마다 별도 타석으로 만들지 않고 미배정으로 남깁니다.
   미배정 투구를 건너뛰어 앞뒤 타석을 합치지도 않습니다.
6. 타자 모드 기본 목록은 목표 선수 ID 근거가 있는 결과만 표시합니다.
   전체 후보, 타자명 일치 근거/신원 미확정, 신원 충돌을 따로 확인할 수 있습니다.
   0건이면 타자 식별 미완료 상태를 표시합니다.
7. 프로젝트 메뉴의 ‘타자명 자막 근거 보기’에서 OCR 시각·관측 이름·주변 문자를 확인할 수 있습니다.
   자막 주변 재생은 타석 경계를 자동 확정하는 기능이 아닙니다.
8. ‘근거 없는 자동 타석 정리 · 검수 보관’은 사용자가 명시적으로 실행합니다.
   검수 이력·타자 정보·확정이 없는 자동 그룹만 해제하고 복원 지점을 남깁니다.
   원본 프로젝트와 검수한 후보를 자동으로 덮어쓰지 않습니다.

## 실영상 결과와 실패

- 기존 KBO 김휘집 개발 샘플: OCR 7회 중 이름 일치 자막 3회, 투구 후보 1개에 이름 근거 1개.
  추가 역할/신원 근거가 부족하여 대상 확정 0, 타석 자동 확정 0입니다. 식별 성공으로 계산하지 않습니다.
- 기존 배영섭 102.4초 개발 샘플(이 환경 분석 약 43.79초; Windows 속도 보장 아님): OCR 52회, 이름 근거 0, 투구 후보 2개, 대상 확정 0, 타석 그룹 0.
  예전처럼 근거 없이 두 타석으로 만들지 않습니다. 이 영상에서 이름 식별은 실패한 상태입니다.
- 다른 경기 그룹의 기존 검증 프레임 4개를 보조자가 먼저 시각 확인했습니다.
  3개에는 강민호/김지찬/구자욱 이름이 보이고 1개에는 타자명이 보이지 않습니다.
  현재 OCR은 강민호 이름 근거만 얻었고 김지찬·구자욱은 얻지 못했습니다.
  이는 프레임 자막 읽기 확인이며 선수 식별 정확도나 전체 경기 성능 수치가 아닙니다.
- 기존 LMB Michael Wielansky 경로: 4개 후보, 이름+팀 대상 근거 3개, 타석 그룹 1개.
  구간 8.7–12.4 / 24.5–28.8 / 48.2–54.6 / 72.3–86.5초를 유지했습니다.
  독립 검수자의 선수 신원·타석·후속 플레이 정답을 검증한 결과는 아닙니다.
- 기존 사용자 프로젝트 사본의 자동 그룹 정리: 박정권 734개 정리/사용자 이력 있는 29개 보존,
  정수빈 117개 정리. 모든 후보는 보존하고 원본 파일은 수정하지 않았습니다.

## 모델·배포·남은 장애물

재사용 기술: 기존 CPU 구도 분류기, 광학 흐름/장면 규칙, Tesseract 및 동봉 tessdata_fast 언어 가중치.
새 객체 검출·유니폼 숫자 모델·선수 추적 모델은 포함하지 않았습니다.
자막 후보 탐색과 현재 타자의 의미적 구분, 작은 한글 자막의 OCR 정확도가 부족합니다.
따라서 일반 중계의 목표 타자 모든 타석 자동 제작 요구는 아직 충족되지 않았습니다.
새 모델·라벨 확보와 미사용 전체 경기 검증 없이 월요일 완성 납품을 보장할 수 없습니다.

로컬 전체 회귀 테스트 102개가 통과했고, 이후 필터 분리 관련 41개 검사도 통과했습니다.
기존 투수·검수·선수 DB·번호 수정·회차 복원·MP4 출력은 Windows에서도 회귀 검사합니다.
Windows 실제 결과는 이번 실행의 build-evidence와 portable-smoke.json을 확인합니다.
EXE 검사 성공과 실경기 타자 식별 성공은 별개입니다.
ZIP은 오류 경로 수정/자막 근거 시험판이며 최종 실사용 타자 식별판으로 안내하지 마세요.
