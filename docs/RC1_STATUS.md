## 실제 변경

1. GUI와 새 인수 시험은 `vision.workflow.analyze_for_review`를 함께 호출한다.
   자동 프로필 선택·사전 진단·규칙 분석·프로필 기록이 같은 경로에 있다.
   옛 모델 계획은 호환을 위해 실행할 수 있지만 `matches_gui_engine=false`이며
   인수 결과 PASS/정식 release 근거로 승격하지 않는다. 자동 후보는 승인하지 않는다.
   출력 시험은 기존 사람 승인 정답만 렌더링한다는 범위도 보고서에 기록한다.
2. release의 모델·실제 독립 경기·상업 이용 검토·성능/경계 조건을 보존한다.
   실제 GUI 엔진 경로와 현재 분석 소스의 해시 일치도 추가 확인한다.
3. 앱 버전은 `bsae.version.APP_VERSION` 단일 값이다. 패키지 메타데이터,
   GUI/도움말, PE 버전, 빌드 정책, ZIP 결과, 생성 사용설명서가 이를 사용한다.
   엔진은 `rules.VERSION`을 기록한다. 커밋·UTC 빌드 시각·분석 소스 해시도 기록한다.
4. 8열 표·분할 미리보기·전체 화면·필터·선수 확인·타석 편집을 재사용한다.
   도구는 창 너비에 따라 그리드로 재배치한다. 타석 도구는 펼치기에서 사용한다.
   영상은 고정 검수 영역에 두고 상단 정보와 하단 도구만 스크롤한다.
   영상까지 스크롤 안에 넣은 시도는 전체 화면 후 Qt 종료 충돌이 재현돼 제외했다.
5. 용어를 선택 선수 플레이 찾기/승인 클립 합본/투구별 개별 MP4/
   타석별 개별 MP4/클립 시작·종료/MP4 저장으로 정리했다. 타수와 타석을 바꾸지 않는다.
6. 집계는 표 필터가 아닌 현재 회차 전체 후보 기준이다. 자동 근거/직접 확인은
   중복될 수 있어 중복 수를 별도 표시한다. 제외 후보 포함 범위와 승인 수도 표시한다.
   작업 진행률 100%는 신원/검수 완료가 아니다.
7. CI는 main, feat/**, fix/**, rc/**를 받는다. ci/* 증거 브랜치는 재빌드하지 않는다.
   rules-preview가 기본이며 기존 native 자산 캐시·대응 소스 배포를 보존한다.
   실제 EXE에서 DPI 100/150/200%·전체 화면 복귀·종료, ZIP 재해제 실행과 SHA를 검사한다.

## 실영상 범위

기존 개발 영상만 회귀에 사용한다. LMB Daniel Martínez 91초 샘플과 KBO 정수빈·강민호
짧은 영상은 실제 전체 디코딩 및 공통 탐색 경로로 재검사한다. 기존 프레임 캐시
재사용 여부와 후보/신원/구간을 비공개 결과 파일에 기록한다.
preview9의 8개 타자 자막 예제 중 5개에 근거가 연결된 결과는 개발 진단이며 독립
정확도 수치가 아니다. 이재현·구자욱 및 한 김지찬 예제의 실패는 남아 있다.
강민호 후속 장면 0–12.7초 보완도 특정 개발 예제의 결과다.
이번 RC에서 새 모델 학습이나 미사용 전체 경기의 성능 검증을 완료하지 않았다.
박정권/정수빈의 접근하지 못한 전체 원본을 분석했다고 주장하지 않는다.
독립 정답이 있는 새 경기 자료가 없어 정밀도/재현율·타석 정확도·작업시간 감소를
새로 산출하지 않는다. 자세한 기존 실험은 BATTER_SCOREBUG_V4.md를 참조한다.

## 검증 및 배포 결과의 읽는 법

- 로컬 합성/GUI 테스트: JUnit 결과를 최종 보고서에 기록.
- Windows EXE·DPI·ZIP: 해당 RC 커밋 Actions의 Windows-build-evidence를 확인.
- portable-package.json: 실제 ZIP 이름/SHA-256/앱 버전/커밋/엔진/빌드 시각.
- portable-smoke.json: 실제 EXE 합성 입력·검수·출력·AV1·라이브러리 검사.
- layout-*.json/png: DPI 환경 변수에 따른 hosted Windows 화면/전체 화면 복귀.
- archive-check.json/unpacked-exe.json: 게시 ZIP을 다시 해제한 실행 검사.
- platform-status.json: 코드 서명 관측값과 사용자 PC/SmartScreen/백신 미검증 구분.
- build-info.json: 같은 빌드의 출처. 사용설명서.txt는 앱 폴더에도 둔다.

성공한 Artifact만 다운로드 가능으로 안내한다. rules-preview RC는 정식 1.0이 아니다.
상업 재배포의 최종 법률 검토·코드 서명·SmartScreen·백신 및 깨끗한 실제 PC 검사는
완료로 표시하지 않는다. 라이선스와 ThirdPartyCorrespondingSources를 함께 보존한다.

## 깨끗한 Windows 10/11 x64 확인 절차 (아직 직접 미실시)

1. Python/FFmpeg/개발 도구 없는 새 VM/PC에서 ZIP 체크섬을 대조한다.
2. 전체 압축을 새 폴더에 풀고 _internal을 유지한다. 기존 버전/프로젝트는 보존한다.
3. EXE 실행 후 도움말에서 버전·커밋을 확인한다. 서명/SmartScreen/백신 관측을 기록한다.
4. 한글·공백 경로의 이용 권한 있는 영상으로 입력 → 선수 지정 → 자동 탐색을 시험한다.
5. 자동/직접 확인/미확인/승인 집계와 근거를 확인한다. 미확인을 통째로 승인하지 않는다.
6. 일부 행 승인·제외, 구간/이닝/투구 번호/타석 수정, 재생/일시정지/전체 화면을 시험한다.
7. 프로젝트 저장·재열기와 선수 목록 재시작 유지, 같은 경기 재탐색·회차 복원을 시험한다.
8. 합본/투구별/타석별 MP4를 출력해 영상·음성·화면비율·후속 장면을 실제 재생 검수한다.
9. 100/150/200% 화면 배율과 작은 창에서 스크롤·8열 표·버튼 접근을 확인한다.
10. 실제 경기 정답 비교는 별도 완전 검수 자료로 실시한다. RC 실행 성공과 혼동하지 않는다.
