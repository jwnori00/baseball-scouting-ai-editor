## 조사한 차단 조건

BLOCKER_AUDIT.csv에 전체 src/packaging Python 소스의 raise/확인창/입력 비활성화 및 빌드 중단 조건을
행 번호와 함께 기록했다. A=필수 데이터 보호, B=불필요한 중복, C=안내로 충분,
D=명시적 사용자 조작으로 해결, E=실제 오류 수정으로 구분했다.
이 목록은 실제 구문과 사용 경로를 조사한 것이며 악성 코드가 있다고 가정하지 않는다.

낮은 수준의 review()/review_many() API의 확인 기본값은 호환성·자동 승인 방지를
위해 보존한다. GUI는 사람의 한 번의 승인 안에서 필요한 기록을 생성하므로
그 오류를 해결하려고 별도 버튼을 반복할 필요가 없다.

## 실제 검수 정책

- 한 개와 여러 개 모두 선택 클립 승인을 사용한다.
- 승인창에 대상 선수, 선택 수, 각 클립 상태(자세히), 함께 확인하는 타석 구성을 표시한다.
- 사용자가 승인하기 전에는 원본 세션을 변경하지 않는다.
- 승인하면 대상 선수 ID, 직접 확인, 시각/클립 승인 이력과 원래 자동 판정을 함께 보관한다.
- identity_status는 자동 판정 그대로이며 manual_identity_confirmed와 구분한다.
- 전체 작업을 복사본에서 검증하고 성공 시 반영한다. 잘못된 구간은 클립 번호와 함께 안내한다.
- 다른 선수/리플레이/자료화면 의심은 명시적 재분류 전 승인하지 않는다.
- 재분류도 선택 범위만 처리하고 이력을 남긴다. 자동 판정이 다른 선수였다는 사실은 보존한다.
- 구버전의 실제 사용자 승인 이력과 대상 ID가 있으면 직접 확인 기록으로 호환 복원한다.
  자동 판정 성공으로 승격하거나 사용자 승인 없는 후보를 승인하지 않는다.

## 타석과 출력

승인 후 해당 타석의 모든 클립이 승인 상태가 되고, 사용자가 승인창에서 그 구성까지
확인한 경우 그룹 확인도 기록한다. 일부가 아직 미승인이면 자동 확정하지 않는다.
타석이 없는 후보들을 임의로 합치지 않는다. 병합/분리는 고급 편집에 보존한다.
투수의 합본·투구별 출력에는 상대 타자 이름/타석 확정이 필요하지 않다.

새 승인 기록은 출력 조건과 일치하므로 같은 선수 확인을 출력에서 반복하지 않는다.
승인되지 않은 후보는 출력하지 않으며, 비출력 제외/견제 후보가 정상 출력을 막지 않는다.
원본 보호, 전체 해시, 시작/종료 유효성, 승인 구간 겹침, 인코딩/음성/전체 디코딩 검사는 유지한다.
저장 창은 승인 수·방식·위치·새 폴더 이름을 한 번에 받는다. 상세 화면비율은 접힌 영역이다.
미확정 타석 그룹은 필요한 경우 같은 출력 창에서 내용을 확인한다.

## 기본 화면

영상 불러오기 / 투수·타자와 이름 / 자동 탐색·중단 / 후보 목록 / 큰 미리보기 /
클립 시작·종료 / 선택 클립 승인·제외 / 구간 수정 / MP4 저장만 우선 배치한다.
투수 모드 상대 타자/이닝/타석 열은 기본에서 숨기며 고급 메뉴에서 표시할 수 있다.
후보는 기본·미확정·다른 선수·리플레이를 쉽게 전환한다. 식별 실패를 성공으로 표시하지 않는다.
상세 통계는 툴팁으로 옮기고 기본은 후보/승인/확인 필요/제외 수를 표시한다.
OCR, 이닝·번호, 타석 편집, 진단, 회차 복원, 방송 보정, 선수 DB, 상세 출력과 분류는
메뉴에 보존한다. 중복 선수 확인 버튼/체크박스/일괄·개별 승인 버튼은 기본에서 제거한다.

현재 프로젝트의 선수는 고정된다. 다음 검색 입력은 다른 선수 찾기에서 바꾸며,
기존 검수/출력은 현재 프로젝트 선수로 처리한다. 새 분석 결과는 기존 검수를 보관한 뒤
전환 여부를 결정한다. 선수 DB와 원시 분석 캐시는 재사용한다.

## 빌드/인수 경로

규칙 기반 GUI와 RC 인수 시험은 vision.workflow.analyze_for_review를 공유한다.
legacy temporal 계획은 호환용이며 실제 GUI 합격으로 표시하지 않는다.
rules-preview 정책과 release의 필수 모델/독립 평가 조건을 유지한다.
빌드는 build-output/<commit-guid>/에 고유 ZIP/SHA를 만들며 기존 ZIP을 삭제하지 않는다.
CI는 기존 ZIP 시험 파일을 보존한 채 빌드하고 새 ZIP의 실제 EXE/재해제 실행을 검증한다.
애플리케이션 Artifact는 검증 후 출력된 새 경로만 게시한다.

## 한계

이번 패치는 검수 편의 개선이며 AI 모델 학습/정확도 향상 검증이 아니다.
개발 KBO 타자 자막의 실패 사례와 미검증 중계는 남아 있다.

깨끗한 사용자 Windows PC·소리 청취·SmartScreen·백신은 hosted Windows 검사와 별도다.
실제 최종 Windows 결과/ZIP/SHA/PR은 해당 커밋의 Actions 증거와 전달 보고서로 확정한다.
