# 통합 검증판: 기능·학습·실영상 검증 상태

**최종 범용 실사용판 합격 기준은 미충족입니다.**
코드·테스트·Windows 실행 성공은 새로운 경기에서 모든 투구/타석과 선수를 정확히 찾았다는 증거가 아닙니다.
이번 ZIP은 기존 출력과 LMB 모드를 보존하면서 학습 구도 시험·검수·로컬 선수 라이브러리·사용자 프로필을 통합합니다.

## 이번 구현

- 다중 선택 일괄 승인, 단일/다중 후보 이닝 수정, 변경 기록과 프로젝트 저장/복원.
- 선수 이름·다른 언어 별칭·리그·팀·등번호·역할·최근 프로젝트·즐겨찾기 로컬 SQLite 저장.
- 분석 완료/프로젝트 저장 시 선수 자동 등록. 선택한 선수의 기존 정보 불러오기와 수정.
- Windows `%LOCALAPPDATA%\BaseballScoutingAIEditor`에 저장하여 EXE/ZIP 폴더와 분리.
- 이름만 같다는 이유로 병합하지 않음. 팀·등번호까지 일치하는 경우만 자동 중복 매칭 시도.
  동일 조건 기록이 여럿이면 선수를 선택해야 하며, 동명이인 별도 등록을 지원.
- JSON 백업·복원. 충돌 시 기존 수정 기록을 덮어쓰지 않고 두 버전을 보존.
- 공식 tessdata_fast 고정 커밋의 한국어/일본어 가중치 추가 및 기존 영어 OCR 유지.
  Apache-2.0 라이선스·출처·SHA-256을 동봉. Windows OCR 실행은 ASCII 임시 경로를 사용.
- 중계·문자 영역 자동 탐색 **시도**. 불확실/미인식 상태를 표시하며 선수 역할을 임의 확정하지 않음.
- 대표 프레임 시각 선택 → 영역 드래그 → 투수·포수·문자 영역 지정 → 사용자 프로필 저장.
- 방송·무스코어보드·고정·이동 촬영 유형 및 프로필은 선수 DB와 분리해 사용자 폴더에 저장.
  고정/이동 촬영은 연결 구조만 제공하며 실제 영상 지원 검증은 미완료. 선수 추적 미구현.
- 기존 LMB 기본 모드, 전체/투구별/확정 타석별 MP4, 720p·30fps·고화질 출력과 자동 여백 제거 유지.

## 실제 학습과 규칙 개선의 구분

구도 분류기는 KBO·MLB·NPB 25개 영상의 실제 프레임 124개에 보조자가 시각 라벨을 붙여 학습했습니다.
밝기 증강 3종은 학습 프레임에만 적용했습니다. 모델은 공간별 밝기/채도/잔디/흙/밝은 유니폼/윤곽 192개 특징과
클래스 균형 가중 정규화 선형 회귀(L2 10)를 사용합니다. NumPy/OpenCV CPU 추론이며 외부 사전학습 동작 모델이 아닙니다.
학습한 것은 투구 **카메라 구도**이며, 투구 릴리스/선수 신원/리플레이/플레이 종료 모델이 아닙니다.
기존 움직임·화면 흐름 규칙과 결합합니다. 다국어 이름 비교·타석 연결·프로필 보정은 별도의 규칙/OCR 개선입니다.

학습 시 파일 SHA-256 및 경기/녹화 계열 그룹의 학습·검증 중복을 차단했습니다.
해시와 파일명은 학습 출처·중복/캐시 관리에만 쓰며 플레이 시간표나 정답 조회에 사용하지 않습니다.
모델은 `profiles/camera-scene-v2.json`, 학습 도구는 `scripts/train_camera_scene.py`입니다.
원본·프레임·선수 DB·비공개 라벨은 공개 GitHub 및 Actions에 올리지 않습니다.

## 검증 데이터와 실제 결과

### 개발 검증

학습에 넣지 않은 8개 파일 32프레임: 투구 구도 12개 중 10개 판별, 2개 누락;
다른 장면 20개 중 4개를 투구 구도로 오판했습니다.
이 중 24프레임은 앞선 개발 검증에 사용됐고, 8프레임은 추가 예제에서 분리했습니다.
KBO(MBC·SBS 등), MLB, NPB 소규모 자료이며 리그 전체 성능으로 일반화할 수 없습니다.

### 모델 고정 후 새로 받은 미사용 예제

추가 영상 8개는 모델 학습에 넣지 않고 가중치·구도 ROI를 바꾸지 않은 상태로 검사했습니다.
대만 중계/스프링캠프, 국가대항전, 스페인어권 중계가 섞여 있으며 정확한 중남미 리그가 확인되지 않은 파일도 있습니다.
실제 디코딩을 확인한 영상의 32프레임 중:

| 실제 프레임 | 투구 구도로 판정 | 다른 장면으로 판정 |
|---|---:|---:|
| 투구 구도 | 15 | 1 |
| 다른 장면 | 1 | 15 |

보조자의 시각 라벨이며 외부 독립 검수자의 확정 정답이 아닙니다.
**이 표는 투구 개수·타석·선수 식별 성능이 아닙니다.**
새 8개 원본을 엔진으로 분석했을 때 후보 수는 순서대로 1, 1, 0, 1, 1, 0, 0, 1입니다.
즉 구도 분류가 좋아 보여도 실제 후보 누락은 남아 있습니다.
특히 국가대항전 및 일부 스페인어권 영상은 후보가 생성되지 않았습니다.
전체 41개 고유 예제에 대한 구도/후보 진단은 비공개 로컬에 보존했습니다.

### 2015 한국시리즈 실영상

102.4초 영상에서 투수 이현승·타자 배영섭 모드를 각각 실행했습니다.
두 모드 모두 후보 2개(0.1–5.2초, 32.6–39.7초), 자동 신원 확인은 0건입니다.
제공된 신원과 보조자의 임시 시각 검수를 적용한 별도 프로젝트에서 MP4 출력·전체 디코딩을 확인했습니다.
투수·타자 각각 투구별 MP4 2개를 생성했고, 타자는 검수로 같은 타석을 묶은 후 타석별 MP4 1개를 생성·전체 디코딩했습니다. 신원 확인·동일 타석 병합은 자동 성공으로 계산하지 않습니다. 영상은 진행 중인 카운트에서 시작합니다.

### 기존 LMB 회귀

기존 설정으로 실제 재분석해 이전과 같은 4개 후보와 경계(8.7–12.4, 24.5–28.8, 48.2–54.6, 72.3–86.5초), 자동 신원 확인 3개/미확정 1개를 확인했습니다. 새 모델로 교체하면 기존 Daniel Martínez 샘플에서 후보가 7개로 늘고 후속 장면이 잘립니다.
따라서 새 모델을 기존 LMB 기본값으로 교체하지 않았습니다.
자동 프로필 선택도 불확실할 수 있으므로 기존 영상에는 검증해 사용한 LMB 모드를 유지해야 합니다.

## 아직 합격 처리할 수 없는 항목

- 새로운 선수의 이름만으로 신원을 자동 확인하는 기능.
- 모든 타자의 모든 타석/투구를 놓치지 않는 자동 탐색 및 정확한 타석 연결.
- 파울/대타/교체/리플레이를 포함하는 전체 경기 독립 정답 검증.
- 수비·주루의 의미상 종료를 자동 판정해 절단하지 않는 보장.
- 고정/이동 촬영에서 목표 선수 시드 지정 및 연속 추적.
- 실제 전체 경기의 투구/타석 정밀도·재현율, 타석 병합/분리 오류율, 검수 시간 절감.

짧게 편집된 예제에는 앞뒤 투구와 타석 일부가 없으므로 전체 경기의 누락률을 계산할 수 없습니다.
별도 경기 원본과 대상 선수별 독립 정답 라벨을 확보해 기존 독립 정답 프로젝트/비교 도구로 평가해야 합니다.
현재 미측정 수치를 0이나 성공으로 채우지 않습니다. 정식 release 자산/성능 게이트는 유지합니다.

## 사용자 실행

새 ZIP을 새 폴더에 모두 압축 해제하고 EXE를 실행합니다. Python/FFmpeg를 따로 설치하지 않습니다.
선수 정보를 입력하거나 라이브러리에서 선택하고, 프로젝트 메뉴에서 중계 유형을 선택합니다.
처음 보는 중계는 자동 탐색 시도를 켜거나 대표 프레임에서 영역을 지정해 저장할 수 있습니다.
모든 신원 미확정 후보·타석·끝부분을 검수하고 승인한 뒤 출력하세요.
라이브러리/프로필은 사용자 폴더에 남으며, 중요한 선수 정보는 JSON으로 백업하세요.
유튜브 URL 가져오기나 제한 우회 기능은 포함하지 않습니다.

## 통합 검증 보충

Linux 통합 회귀 65개가 통과했습니다. Windows EXE에서는 한글 설치 경로, 동봉 구도 모델 무결성, 영어/한국어/일본어 OCR 로딩, 일괄 승인·이닝 수정, 720p·30fps 출력, 별도 EXE 프로세스의 선수 DB 재조회 검사를 수행하도록 구성했습니다. 실제 결과는 ZIP의 `build-evidence/portable-smoke.json`과 해당 Actions 실행 기록을 확인하세요.

중계 자동 선택 시도를 실제 기존 샘플에 실행해 LMB는 팀/레이아웃 근거 5회로 기존 프로필을 선택했고, 2015 KBO는 일반 모델을 선택하되 `UNCERTAIN`으로 남겼습니다. 이는 미사용 경기의 프로필 선택 정확도 측정이 아닙니다.

세 언어 가중치 동시 로딩과 실제 영상에서 일부 한글 스코어보드 문자 인식을 확인했습니다. 해당 시험에서 선수 이름을 자동 확인한 것은 아니며 글자 점수를 신원 정확도로 해석하지 않습니다.

Windows 통합 빌드에서 테스트 65개와 EXE 생성 후 DB 임시 파일 정리가 실패한 이력이 있습니다.
원인은 SQLite 연결의 컨텍스트 종료가 연결 자체를 닫지 않아 남은 Windows 파일 잠금입니다.
연결을 명시적으로 닫도록 수정하고, DB 조회·저장·복원 후 파일 이름 변경/삭제가 가능한지 검사하는 회귀 테스트를 추가했습니다.
